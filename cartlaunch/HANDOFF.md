## 작업 절차 (매번)

1. 수정 → `node -e "require('./cartlaunch/core.js')"` 로 문법 확인.
2. 브라우저 테스트(아래) → 커밋 → `git push -u origin ccr-16eb7d18-ghxjxq`.
3. 게시: Artifact 도구 `publish`, `file_path: cartlaunch/index.html`, `url`: 위 주소, `files: {"core.js": "cartlaunch/core.js"}`.
   - `capabilities`는 **넘기지 않는다**(이미 `db`, `user`가 선언돼 있고 생략하면 유지됨). `{}`를 넘기면 계정 저장이 꺼진다.

4. 사용자에게는 무엇이 바뀌었는지와 확인한 범위를 한국어로 짧게 알린다.

## 테스트

저장소 루트에서 로컬 서버를 **테스트할 때만** 띄우고 끝나면 끈다: `(python3 -m http.server 8766 >/dev/null 2>&1 &); sleep 1; …테스트…; pkill -f "http.server 8766"`. 백그라운드로 오래 띄워 두면 실행 제한 시간에 꺼진다. 인자는 `saves.json`이 있는 폴더.

- 로컬 서버는 백그라운드 실행 제한 시간이 지나면 꺼진다. 위처럼 테스트 명령과 한 줄로 띄우고 끄는 편이 안전하다.
- 화면 크기별 트리 높이 확인: 2560×1440, 2048×1152(2K 125%), 1920×1080, 1366×768, 844×390에서 각 탭의 `.nd` 아래 끝이 `#sList` 높이 안에 드는지 잰다.
- 페이지의 `window.__cart` 로 내부 상태에 접근한다(`C, S, run, state, launch, toAim, openShop, save, charge, MUS, CLOUD, slot, peek, OPT, PERF, Q, AUD, liveSnap, liveStore` 등). `S`와 `run`은 함수가 아니라 값이다.
- 구글 폰트 요청은 테스트에서 막는다(`route(/fonts\./)`).
- 봇(`tools/bots.js`: pilot·trick·idle)은 사람만큼 조작을 못 한다. 조작 관련 수치는 봇 결과를 그대로 믿지 말 것.

## 반복해서 낸 실수 — 반드시 피할 것

- **영어로 쓰기**: 답변·작업 목록 제목·명령 설명·파일 캡션까지 사용자에게 보이는 글은 전부 한국어(사용자가 두 번 지적함).
- **사용자가 고쳐 둔 것을 디자인하다 되돌리기**: 버전 82에서 오른쪽 고정 패널이 다시 들어와 사용자가 11-23에 고친 '노드 옆 카드'를 덮었다. 큰 화면 개편 전에는 아래 '사용자가 정한 것'을 먼저 확인할 것.

- **줄 중간에 `//` 주석을 붙이면 그 줄의 나머지 코드가 통째로 주석이 된다.** 이 프로젝트는 한 줄이 매우 길어서 여섯 번이나 같은 사고가 났다(초월이 깨진 채 커밋된 적도 있음). 주석은 **항상 별도 줄**에 쓴다. 파이썬으로 문자열을 치환할 때 특히 주의.
- 치환 전 `assert s.count(a) == 1` 로 대상이 정확히 한 곳인지 확인한다.
- 소리는 들어 볼 수 없다. 오류 없이 재생되는지만 확인되므로 사용자에게 그렇게 말한다.

## 사용자가 정한 것 (다시 묻지 말 것)

- **상세 창은 무조건 누른 노드 바로 옆 카드(버전 81 방식)**. 오른쪽에 붙는 고정 패널은 쓰지 않는다(눈이 한 번 더 오른쪽으로 가야 해서). 11-23에 사용자가 고쳤는데 버전 82 트리 재디자인 때 고정 패널이 다시 들어왔고, 버전 103에서 다시 카드로 되돌렸다. 카드는 `popAt()`이 타일 오른쪽(안 들어가면 왼쪽)에 놓고, `treeHTML`·`transGridHTML` 안에 그린다. 빈 곳을 누르거나 ✕로 닫는다. 화면 아래쪽 절반의 타일은 카드가 위로 열린다(카드 아래 끝 = 타일 아래 끝, `showDetail`).
- **트리는 아이콘 크기를 줄이지 않고 화면 높이에 맞춘다**(사용자 요청, 버전 105): 줄이 화면보다 길면 이름표 높이(`lbl`, 최소 44)와 연결선 띠(`gap`, 최소 16)만 줄이고, 그때는 이름을 한 줄로(`.tw.tight`) 쓰며 칸 폭을 넓힐 수 있다. 트리 시작 위치는 렌더 뒤 재서 `TREE.off[tab]`에 두고 다르면 한 번 다시 그린다. 2K 125%(2048×1152)·FHD에서 차체·장치·수익은 한 화면, 환생은 위 막대 때문에 마지막 줄이 조금 잘림(아이콘을 줄여야 해서 그대로 둠).
- **불사조·슈퍼 불사조** (버전 106, 사용자가 정함):
  - 불사조 부활 때 최고 속도 한도는 발사 직후 한도의 **70%**까지만 회복(`r.fresh = max(지금, tr − tire·ln(1/0.7))`). 도약·대시 +1은 그대로.
  - **슈퍼 불사조** `t_sphx`(초월 속도의 길, ◆200 / 5,000 / 100,000). 레벨마다 해금 구역이 다르다: Lv1 미지의 영역 7 · Lv2 15 · Lv3 30 (`C.tGate`, 버전 107). 불사조 없이도 부활한다.
    - Lv1/2/3: 발사 직후 한도의 **1.1/1.3/1.5배 속도로 2/3/4초 질주**(`r.sphxT`, `sphxSpeed`), 끝나면 한도 100%에서 평소처럼 줄어듦.
    - 불사조 도약·대시·급강하 **2/3/5회**, 불사조 부스터 **+50/70/100%**.
    - **변신** (버전 110, 사용자가 정함 — 버전 109의 '부활 뒤 전환 버튼'을 대체): 슈퍼 불사조는 한 판에 한 번, 두 가지로 쓰인다.
      ① 비행 중 언제든 작은 '🔥변신' 버튼(`#sphxBtn`, 대시 버튼 오른쪽, 키 **Q**, 숫자 표시 없음)으로 그 자리에서 효과를 미리 쓴다. **변신한 판은 멈춰도 부활하지 않는다**(`r.risen = true`, 시간 +30초는 붙음).
      ② 변신 안 하고 멈추면 불사조 부활을 슈퍼 불사조로 덮어씌워 발동.
      효과(`sphxGo`)는 둘 다 같다: 질주, 레벨별 불사조 스킬, 불사조 부스터, 그리고 가진 일반 도약·대시·급강하를 **전부** 불사조 스킬로(도약 3개·대시 2개·급강하 2개당 1개, 남는 묶음도 1개: 도약 11→4, 대시 9→5). 규칙 `CONV`·`convOf`·`canSphx`·`sphxGo`, 입력 `inp.sphx`, 이벤트 `sphxon`(비행 중 변신)·`phoenix`(부활). 예전에 급강하였던 Q키는 변신으로 옮겼다(급강하는 S·↓).
      설명 문구는 사용자 요청대로 '즉시 슈퍼 불사조로 언제든 변신 가능 · …'.
    - 불사조 스킬이 먼저 쓰인다. 불사조 대시: 피로 회복 2.5배(12.5%). 불사조 도약: 대시의 80%만큼 앞으로 + 피로 10% 회복(일반 도약은 회복 없음). 불사조 급강하: 0.38초 날개 펴고 기 모은 뒤 일반보다 빠르게 낙하(`r.pdc`, `r.fdive`), 착지는 일반 슬램과 같음.
    - **부스터 두 겹**: 붉은 게이지(`r.fuel`, 최대 100%) 위에 주황 불사조 게이지(`r.pfuel`)가 덮인다. 불사조 쪽이 먼저 닳고, 그동안 피로 회복 2.5배. 재급유는 붉은 게이지만 채운다. 100%+100% = 200%로 표시.
  - 화면: 버튼에 '🔥N · M회', 주황 테두리. `fireWings`·`phoenixOnCart`(기 모으기 날개, 대시·도약 날개 번쩍, 질주 불꽃), 불사조 부스터는 붉은·주황 불꽃, 불사조 급강하 꼬리·화면 효과는 주황.

- **불사조 급강하 속도** (버전 111, 사용자 요청): 기 모으기 0.38초 동안 예전에는 앞속도·세로속도를 모두 깎아 앞속도가 3%까지 떨어졌다(착지 직후 발사 속도의 73%→41%). 이제 세로만 멈추고 앞속도는 그대로(73%→기 모은 뒤 82%→착지 76%, 일반 급강하는 70%). `sphx.js`에 검사 있음.
- **속도 한도 회복 수치** (사용자에게 알려 준 값, 지구력 만렙 = 시간 상수 60초): 아무것도 안 하면 1초에 한도 −1.65%. 버전 101까지 대시·부스트는 회복 0. 버전 102부터 부스트 1초 +0.84%(피로 0.5초 감소), 불사조 부스터 1초 +2.11%(1.25초), 대시는 쌓인 피로의 5%, 불사조 대시 12.5%, 불사조 도약 10%, 일반 도약 0. 불사조 부활은 한도 70%까지, 슈퍼 불사조는 100% + 질주.
- **점프대 킥 빛** (버전 110): 카트가 점프대 꼭대기 흰 원에 닿는 순간(`pushT >= KICK_AT - 0.03`) 원이 0.35초 동안 노랗게 빛난다(`kickGlowAt`). 문구는 넣지 않는다(사용자 요청).
- **근력 400 → 350 문의** (11-25): 버그가 아니라 자동 환생 때문. 전생의 기억 Lv10이면 환생 때 레벨의 80%만 남아 근력 400 → 320, 그 뒤 창업 자금(최고 판 수입 100%)으로 자동 구매가 되사는데 수입 10^95이면 350, 10^101이면 377, 10^102이면 393에서 멈춘다(근력 350 이후 레벨당 가격이 10^95 → 10^101). 사용자도 원인에 동의. 막는 방법(환생 때 근력 유지 등)은 제안만 하고 규칙은 안 바꿈.

- 새 구역 골드는 기본 금액에 포함되어 보너스가 곱해지는 방식.
- 우주 가속기는 빅뱅 점화보다 비싸야 한다.
- "다른사람의 계정은 건들이지말고 불확실하면 수정하지마" — 다른 플레이어의 저장을 바꾸는 코드는 절대 넣지 않는다. 본인 저장만 다루는 버튼(골드만 비우기, 처음부터 다시)과 본인 전용 계정 저장만 있다.
- 숫자 표기는 만·억…극·항하사·아승기·나유타·불가사의·무량대수, 그 위는 "만 무량", "무량²" 식.

## 버전 82에서 바뀐 화면 구조 (2026-11-24)

**규칙(`core.js`)은 건드리지 않았다.** 사용자가 "밸런스 조정은 먼저 무엇이 바뀌는지 말하라"고 했으므로, 수치 변경은 반드시 제안 → 승인 뒤에 한다.

- **설정** (`OPT`, 기기 저장 `cart.opt`): 그래픽 모드(자동·절전·균형·화려함 = `QL.low/mid/high`), 프레임 제한, 화면 흔들림, 번쩍임, 글자 효과, 진동, 효과음·음악 크기, 성능 표시. 탭 `opt`, 상단 "설정" 버튼.
  - 모드별로 켜지는 것은 `QL` 표 한 곳에 있다(`dpr, part, cap, cnt, glow, haze, far, shade, shadow, rays, vig, trail`). 새 효과를 넣을 때는 `Q.<이름>`으로 감싼다.
  - 자동 모드(`perfTick`)는 비행 중 프레임 시간을 "화면이 허용하는 속도(`PERF.base`)"와 비교한다. 기본은 균형에서 시작, 여유가 있으면 화려함으로 올리고, 무거웠던 단계는 최대 두 번만 다시 시도한다(`cart.autoq`, `cart.autofail`).
  - 상점이 열려 있는 동안은 캔버스를 그리지 않는다.
- **소리** (`AUD`): 효과음 → `sfxG`, 음악 → `musG` → 로우패스 → 리미터. 잔향 보내기(`tone(…, { rev })`), 큰 타격 때 음악 줄임(`AUD.duck`), 결과·상점에서 음악 먹먹하게. 코인 소리는 지금 나오는 곡의 화음을 따라 올라간다(`coinHz`, `MUS.key()`).
- **진행 중인 판 이어 가기**: 게시하면 뷰어가 열린 페이지를 알아서 새로고침한다. `liveSnap()`이 비행 상태를 넘기고(`window.claude.hot.snapshot`, 그리고 기기 저장 `cart.live`에 2.5초마다·페이지가 가려질 때), 새 페이지의 `liveRestore()`가 같은 지점에서 이어 간다. 판이 끝나면 "새 버전이 적용됐어요"가 뜬다.
  - 조건: 슬롯과 `S.runs`가 같아야 하고(이미 정산된 판은 다시 살리지 않음), 기기 저장본은 90초·hot 데이터는 5분보다 오래되면 버린다.
  - `run.st`는 발사 때 값을 그대로 쓰고, 새 버전에서 추가된 항목만 현재 값으로 채운다. **`run`에 JSON으로 못 옮기는 값(Set 등)을 추가하면 `liveSnap`/`liveRestore`도 같이 고칠 것.** (`used`만 Set ↔ 배열 변환)
  - 플랫폼의 `preflight.js`(게시 때 열린 페이지에 대해 실행되는 예약 파일)는 규격을 확인하지 못해 쓰지 않았다.
- **상점**: 트리는 `layoutTree` → `treeHTML`(타일 + 진행 링 + 상태 배지, 직각 연결선 `orth`), 상세는 누른 타일 옆 카드 `popAt`(`upDetail`/`perkDetail`/`transDetail`), `showDetail`은 카드가 보이게 스크롤만 한다. 트리는 양방향 드래그 이동.
  - 환생 탭은 `starOpen()`(망망대해 35km 도달 또는 환생·별 이력)이 될 때까지 베일(`.veil`)로 가려지고 "35km 해금"만 보인다. 초월 탭은 기존대로 조건 전에는 아예 없다.
  - 환생·초월 막대는 칩 3개 + 버튼. 초기화·유지 설명은 확인 단계("정말요?")에서만 나온다.
- **지도 탭** (`MAP`, `mapMount`/`mapLayout`/`mapTick`/`mapScene`, 버전 85): 가 본 구역(`C.reached(S)`까지)을 필름 한 칸씩으로 보여 준다.
  - 칸은 완만한 원통 위에 놓인다(`MAP_A` = 칸 사이 각도, CSS 3D). 드래그·휠·방향키·좌우 버튼·옆 칸 탭으로 넘긴다. 좌우 버튼이나 방향키를 누르고 있으면 `mapHold`가 속도를 0.45초마다 두 배로 올려(최대 초당 90칸) 끝까지 굴린다. 빠르게 구르는 동안 새 칸의 그림은 미뤘다가 멈춘 뒤 그린다(`dirty`).
  - 칸 그림은 게임의 `backdrop()`을 작은 캔버스에 그대로 그린 것(`g, W, H, horizon, bgScroll`을 잠시 바꿔 호출). 가운데 칸만 계속 다시 그려 천천히 흐른다. 이번 생의 구역 칸에는 카트가 서 있다.
  - **남은 구역 수를 알 수 없게 하는 것이 요구 사항이다.** 못 가 본 곳은 검은 "??" 한 칸뿐이고 그 뒤는 구멍만 난 빈 필름이 흐려진다. 같은 이유로 상점 머리글의 "11 / 30"과 기록 탭의 구역 목록을 없앴다. 전체 구역 수가 드러나는 표시를 새로 넣지 말 것.
- **휴대폰 화면** (버전 87): 사용자는 claude.ai 사이트에서 플레이하므로 브라우저 주소창과 사이트 머리줄만큼 높이가 줄어든다(가로로 든 폰은 약 844×290). `layout()`이 `#root`에 `sm`(높이 440 미만), `xs`(345 미만)를 붙이고 CSS·`treeHTML`이 그에 맞춰 줄인다.
  - 트리: 작은 타일(46px)·좁은 칸, 가로보다 훨씬 깊은 트리(발사)는 옆으로 눕혀(`flip`, `orthH`) 한 화면에 넣는다. 휴대폰에서 좌우로 밀어야 하는 트리가 없어야 한다.
  - 결과 카드: 머리와 버튼은 고정, 가운데(`#rBody`)만 스크롤. "다시 밀기"가 화면 밖으로 밀리면 안 된다.
  - `xs`: 탭이 아이콘 두 줄이 되고 탭 이름은 머리글에 나온다.
  - 화면 확인은 `node cartlaunch/tools/e2e/phone.js <출력폴더> [가로] [세로]`(겹침·스크롤 여부도 출력).
  - 상단 "전체 화면" 버튼(`#fsBtn`)은 브라우저가 허용할 때만 보이고, 거절되면 숨는다. 사이트 머리줄 자체는 페이지 밖이라 없앨 수 없다.
- **연출**: 히트스톱 `hitStop`, 카트 스쿼시 `sqz`, 줌 펀치 `punch`, 탑승자 표정 `mood`(0 보통·1 놀람·2 충격·3 기쁨)와 목도리(`doll.sc`), 글자 팝업은 `pop()`으로만 넣는다(같은 문구는 ×n으로 합침).
- **엔딩** (`drawEnding`): 매장 배경·계산대 73 표지·계산원·기념품 10개 스캔(`souvenir`)·영수증(바코드, 도장)·불꽃·첫 엔딩 보상 알림.

## 사용자에게 제안해 두고 답을 기다리는 밸런스 항목 (적용 안 함)

(창업 자금·전생의 기억 건은 버전 84에서 처리됨.)

1. 첫 생에서 망망대해 → 만년 설산이 39판, 바로 다음 용암 지대는 4판(조종 봇 기준)으로 고르지 않다.
2. 알파 센타우리 이후 한 판 수입이 가격 기준(`gref`)의 15~300배라, 근력 훈련을 뺀 업그레이드는 열리자마자 만렙이 된다. 수입의 80~93%가 코인·상자다.
3. 환생 트리 "끈기"(제한 시간 +10초)와 초월 "지구력"은 빠르게 튕기고 환생하는 플레이에서는 값이 거의 없다.

## 검증되지 않은 것

- 실제 카카오톡 앱 안 브라우저와 실제 로그인 계정에서의 계정 저장·저장 코드 옮기기(카카오톡 사용자 에이전트를 흉내 낸 헤드리스 브라우저로만 확인).
- 사용자 실제 2K 화면에서의 트리 배치(2048×1152 창 크기로만 확인).
- 슈퍼 불사조의 장기 밸런스(규칙·화면은 확인, 봇 비교는 안 함). 불사조 울음소리는 오류 없이 재생되는지만 확인.

- 실제 계정으로 다른 기기에서 이어받는 동작(가짜 저장소로만 테스트).
- 새 음악 9곡과 발사 효과음의 실제 소리, 버전 82의 믹싱·잔향·코인 음계(오류 없이 재생되는지만 확인).
- 실제 게시 환경에서 `window.claude.hot`가 주는 데이터의 모양(안내문에 적힌 방식대로 구현했고, 가짜 hot과 기기 저장 경로로만 테스트). 기기 저장 경로가 따로 있어 hot이 없어도 이어진다.
- 실제 휴대폰에서의 프레임 수(헤드리스 브라우저는 CPU로 그려서 '화려함'이 47fps까지 떨어졌고, 자동 모드가 균형으로 내리는 것까지 확인).
- 초월을 여러 번 거듭하는 장기 진행 속도(한 주기만 시뮬레이션).
- 근력 360~400 구간의 실제 체감(가정한 별 수와 다르면 크게 달라짐).
